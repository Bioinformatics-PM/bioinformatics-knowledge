# RFC 4180

> [!abstract]
> The IETF document that writes down the common CSV format (records, commas, optional header, double-quote quoting) and registers the `text/csv` media type.

## Why this source

CSV existed for decades without a specification; RFC 4180 is the closest thing to one. Its seven rules and its short ABNF grammar are what the Python `csv` module's default dialect and most spreadsheet exports follow, so it is the reference for deciding whether a file is well formed and which fields must be quoted.

## How to use it

- L1: read section 2 (one page) before writing a CSV parser or validator.
- L2: compare its rules with a real export (spreadsheet, database) to spot the deviations your reader must tolerate.

## Caveats

- Category "Informational": it documents existing practice and does not define an Internet standard; many programs deviate (other delimiters, LF line endings, no quoting).
- Says nothing about tab-separated files, comments, encodings beyond the `charset` parameter, missing values or types: those are conventions of each format built on top (BED, GFF, VCF).
- A revision has been drafted at the IETF (`draft-shafranovich-rfc4180-bis`); RFC 4180 remains the published version.
- Verified in this pass: number, title, author, October 2005 date, Informational category, the double-quote and CRLF rules and the `text/csv` registration.
